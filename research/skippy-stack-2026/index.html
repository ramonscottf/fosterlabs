Skills, sub-agents, harnesses, and Managed Agents — the terminology actually disambiguated.

Anthropic's surface area exploded between October 2025 and April 2026, and the words people use are imprecise. Here is the canonical map.

Agent Skills — the open standard

Launched October 16, 2025 in Anthropic's engineering post "Equipping agents for the real world with Agent Skills". On December 18, 2025 Anthropic published Skills as an open standard at agentskills.io with a reference SDK, a Discord, org-wide enterprise management, and a "quick-create flow" UI in Claude.ai.

By Q1 2026 the standard was adopted by OpenAI (Codex CLI, ChatGPT), Microsoft (VS Code/GitHub Copilot), Cursor, Goose, Amp, OpenCode, Gemini CLI, and Antigravity — same SKILL.md filename, same metadata format, same directory layout.

MCP provides secure connectivity to external software and data, while skills provide the procedural knowledge for using those tools effectively. — Mahesh Murag, Anthropic PM // December 18 2025

A skill is a directory containing a single required file:

my-skill/
├── SKILL.md          # required: YAML + Markdown
├── scripts/          # optional executable code
├── references/       # optional docs
└── assets/           # optional templates

Required frontmatter: name (lowercase, hyphens, ≤64 chars), description. Anthropic's Claude Code adds optional extensions: when_to_use, argument-hint, disable-model-invocation, user-invocable, allowed-tools, model, effort, context: fork, agent, hooks, paths, shell.

Progressive disclosure is the design centerpiece: agents preload only name + description at startup (~30 tokens per skill); the body loads when triggered (500–2,000 tokens); bundled scripts/references load only on execution. This is the architectural reason Skills are often described as "more efficient than MCP."

Formal Skills vs. random GitHub repos

The distinction Scott asked about is real and worth keeping straight. Formal Agent Skills come from github.com/agentskills/agentskills with the reference SDK at agentskills.io, stewarded by Anthropic, cross-tool compatible by design, with examples at github.com/anthropics/skills. The other "skills" repos are author-owned implementations that follow the SKILL.md format — quality, naming, and maintenance vary wildly, and compatibility is advertised but rarely tested.

Sub-agents vs. agent teams vs. Managed Agents

Three distinct primitives that get conflated. Here is the actual difference:

SUB-AGENTS
Local Claude Code/SDK process. Isolated fresh window per sub-agent. Configuration via .claude/agents/*.md. Cost = token cost only. Best for delegated research, focused subtasks. Status: GA.
AGENT TEAMS
Multiple CC instances coordinating in parallel. Independent windows per teammate. Direct comms via shared task list. Behind CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1. ~7× tokens in plan mode. Do not deploy in prod.
MANAGED AGENTS
Anthropic's cloud. Durable session log + harness-managed window. Survives disconnects. Reusable Agent IDs. Cost = tokens + $0.08/session-hour. Best for production product integrations, long async work. Status: public beta (April 8, 2026).

Built-in sub-agent types: Explore (Haiku, read-only search), Plan (gathers context, read-only), General-purpose (full read/write). Agent Teams docs explicitly warn of "known limitations around session resumption, task coordination, and shutdown behavior."

Agent harness — the term defined

This is explicitly Anthropic terminology. Cleanest definition is from the April 8, 2026 engineering blog "Scaling Managed Agents: Decoupling the brain from the hands":

We virtualized the components of an agent: a session (the append-only log of everything that happened), a harness (the loop that calls Claude and routes Claude's tool calls to the relevant infrastructure), and a sandbox (an execution environment where Claude can run code and edit files). — Lance Martin, Gabe Cemaj, Michael Cohen // April 8 2026

A harness contains: tool dispatch, permission gating, context management (compaction, caching, CLAUDE.md re-read), retry/error recovery, sub-agent dispatch, and session/state management.

Anthropic's own framing: model = generates text; harness = the deterministic code wrapping the model; agent = model + harness + tools + configuration. The April 8 rallying cry: "Harnesses encode assumptions that go stale as models improve." This is why Managed Agents exposes the harness as a swappable component.

Claude Managed Agents — the April 8, 2026 product

A suite of composable APIs for cloud-hosted agents. Beta header managed-agents-2026-04-01. Four core concepts: Agent (model + system prompt + tools + MCP + skills), Environment (cloud container template), Session (running instance, durable append-only event log), Events (messages exchanged between app and agent). Built-in tools: Bash, file ops, web search/fetch, MCP connector. Pricing: standard token rates + $0.08/session-hour while running. Rate limits: 300 create-requests/min, 600 read-requests/min per org.

Hooks — full surface and token-reduction patterns

26 lifecycle event types across the Claude Code lifecycle (per Blake Crosley's analysis of v2.1.116):

PER SESSION

  • SessionStart, SessionEnd

PER TURN

  • UserPromptSubmit, UserPromptExpansion, Stop, StopFailure

PER TOOL CALL

  • PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, PermissionDenied

SUBAGENTS

  • SubagentStart, SubagentStop

MAINTENANCE

  • PreCompact, PostCompact, Setup, Notification, ConfigChange, FileChanged, CwdChanged, PostToolBatch

Handler types include command (shell), HTTP (new February 2026 — POST event JSON to a URL with headers and allowedEnvVars), async (async: true, January 2026), prompt (single-turn Haiku evaluation — much cheaper than full Claude reasoning), and agent (full subagent runs).

HOW HOOKS REDUCE TOKENS — THE LEVERAGE YOU WANT

  1. PreToolUse permissionDecision: "deny" blocks expensive recovery turns. Critically, this works even in bypassPermissions mode or with --dangerously-skip-permissions — non-bypassable team policy enforcement.
  2. PostToolUse summarization intercepts a 50K-token bash output and replaces it with a short summary; only the summary enters context.
  3. SessionStart context injection loads git status + TODOs deterministically (200 tokens) instead of letting Claude waste 5K of plan-mode investigation.
  4. PermissionRequest auto-approve for safe prefixes eliminates back-and-forth permission tax (typically 30% of round-trips).
  5. Stop-hook prompt evaluator (Haiku) gates "I think I'm done" loops at $1/M input vs. Opus reasoning at $5/M.
  6. PostToolUse format-on-save prevents Claude from making style-correction passes after writes.

Pixelmojo reports a 45% vulnerability-rate reduction from hook-based pre-edit gating; Blake Crosley runs 95 hooks across 6 event types with ~200ms total overhead by using single dispatchers per event rather than independent hooks.

CLAUDE.md best practices, 2026 consensus

Keep it concise. For each line, ask: "Would removing this cause Claude to make mistakes?" If not, cut it. Bloated CLAUDE.md files cause Claude to ignore your actual instructions! — Anthropic, code.claude.com/docs/en/best-practices

Community consensus from Marmelab (Apr 24 2026), computingforgeeks, Druce.ai, Simon Willison's Agentic Engineering Patterns, Sankalp's blog, Batsov.com:

  1. Under 200 lines is the ceiling. Bloat actively degrades performance.
  2. Move conditional knowledge to skills, not CLAUDE.md.
  3. @-imports for large reference docs (@AGENTS.md, @docs/git.md).
  4. AGENTS.md as canonical, CLAUDE.md as a thin shim — Copilot, Codex, Cursor, Windsurf, Cline, Antigravity, OpenCode all read different files; AGENTS.md is the lowest-common-denominator that emerged in late 2025.
  5. Path-specific rules in .claude/rules/ only load when Claude touches matching files.
  6. Use hooks for guarantees — anything that must happen (lint after edit, no force-push to main) goes in a hook, not in CLAUDE.md instructions; hooks are deterministic, CLAUDE.md is advisory.
  7. Run a retro every session: ask Claude what it learned; route to ADRs / rules / skills / CLAUDE.md.

Prompt caching state in 2026 — and the silent regression you need to know about

Mechanics: mark a content block with "cache_control": {"type": "ephemeral"}. Cache reads cost 10% of standard input price (90% savings). Up to 4 breakpoints per request. Caches are workspace-isolated as of February 5, 2026 (was org-isolated). Min cacheable prefix 1,024 tokens. TTL options: 5m (default, write costs 1.25× input) or 1h (write costs 2× input). Pays for itself after 1 read at 5m, after 2 reads at 1h. Reads do not count against your TPM rate limits.

THE SILENT REGRESSION OF 2026

On March 6, 2026 Anthropic silently changed the default TTL for cache_control: {type: "ephemeral"} from 1 hour to 5 minutes — no changelog, no blog post. Disabling telemetry also kills the 1-hour TTL (silent coupling).

For Claude Code subscribers, JSONL analysis (GitHub issue #46829) showed 17.1% measured cache-cost waste across 119,866 API calls (Jan 11–Apr 11, 2026) on both Sonnet 4.6 and Opus 4.6 driven entirely by the 5m/1h split.

FIXES YOU NEED TO APPLY RIGHT NOW

  • API users: set "ttl": "1h" explicitly in every cache_control block, and add anthropic-beta: prompt-caching-2024-07-31.
  • Claude Code v2.1.105+: set ENABLE_PROMPT_CACHING_1H=1 in your shell profile.
  • Avoid --resume for long sessions — leaked source analysis showed it triggers full context reprocessing billed as new input.

Anti-patterns that silently kill cache hits: timestamps in cached prefix (truncate to day), user-specific content in cached system prefix, single-character whitespace drift, attestation drift (per-request data Claude Code attaches that varies — confirmed by the March 31, 2026 source leak).

Reported real-world savings when configured correctly: 60–90% on input tokens; aimagicx.com case study: 65% measured savings on 1.8K-token system prompt + 14K diff + 5K codebase + 7K tool defs across three workloads.

/clear vs. /compact strategy

The fundamental cost problem: every turn re-sends entire conversation history + system prompt + CLAUDE.md + MCP tool defs + tool results. One developer measured 98.5% of tokens spent re-reading history, 1.5% on actual output.

  • /clear drops conversation entirely (keeps MCP servers, skills, parsed CLAUDE.md). Use between unrelated tasks. Risk: waiting >5 min after /clear expires the prefix cache; next turn pays a full cache write.
  • /compact [focus] summarizes and continues; preserves architectural decisions, file diffs, current task state, errors and fixes. Cache stays warm. Auto-compaction triggers around 187K tokens (or 76K on Opus 1M, wasting 92% of available window). Each compaction can cost 100–200K tokens. Use /compact <focus instructions> for steering. Override: CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000.

The autocompact infinite-loop bug (March 2026): leaked source revealed 1,279 sessions with 50+ consecutive failures (up to 3,272) — wasting ~250K API calls/day globally. Fix shipped April 1, 2026 in v2.1.89: MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES = 3. Update to v2.1.116 or later.

THE IDLE DRAIN — WHAT ACTUALLY HAPPENED

Three independent things converged Q1–Q2 2026, all confirmed in Anthropic's April 23 postmortem (anthropic.com/engineering/april-23-postmortem):

Reasoning silently downgraded
Mar 4 → Apr 7. Default reasoning effort silently dropped from high to medium to address UI freezes from long thinks. Caused shallow "edit-first not research-first" behavior. Reverted; Opus 4.7 now defaults to xhigh.
SEVERITY :: MEDIUM
The thinking-block cache bug (the most expensive bug)
Mar 26 → Apr 10. A caching optimization meant to clear Claude's older thinking blocks once after >1h idle had a bug — it cleared them on every turn for the rest of the session. Claude appeared forgetful, repeated work, redid investigations; the cache layer that should have absorbed cost was broken. Single most likely root cause of "Max 20× exhausted in 70 minutes" reports.
SEVERITY :: CRITICAL
25-word response cap
Apr 16 → Apr 20. A system-prompt instruction capping responses at 25 words between tool calls and 100 words for final responses. Measurably hurt coding quality (3% Opus eval drop). Reverted in 4 days.
SEVERITY :: HIGH

All three resolved by April 20, 2026 (v2.1.116). API was not affected.

Layered on top: the autocompact infinite-loop bug, the attestation drift cache-invalidation bug (one Max 20× user's cache reads collapsed to 36% — should be 90%+), plugins injecting tool defs every turn (5 idle plugins ≈ 55K tokens before you type), MCP servers loading 18K tokens of schemas per turn (5 servers = 90K overhead — Tool Search reduces this by 95%), sub-agent fan-out on Opus 4.6 (one user spawning 5 parallel sub-agents unprompted, hitting Pro 5h limit in 15 minutes), --resume reloading and re-billing full conversation history, and an unfixed silent tool-result truncation bug at the 200K aggregate threshold (still active in v2.1.91).

AMD's Stella Laurenzo (Issue #42796) published the most rigorous public analysis: 6,852 sessions, 234,760 tool calls, behavioral regression starting March 8. Her February bill: $345. March: $42,121. AMD switched providers.

SUBSTANTIVE CRITIQUES

  • Token bloat: Firecrawl's 75-run study: CLI 1.3K–8.7K tokens vs MCP 32K–82K, MCP 72% reliable vs CLI 100%.
  • Eager loading: every session loads all schemas.
  • Composability: CLIs compose via bash; models already know git/gh/kubectl/jq from training.
  • Auth complexity: multiple OAuth flows per server.
  • Security: 24% of public MCP servers have zero auth per Zuplo; Bloomberry put it at 38.7%; OWASP MCP Top 10 published early 2026; lethal-trifecta prompt injection; the fake Postmark MCP that BCC'd emails to attackers; the Supabase MCP SQL-injection via support tickets.
  • Process management: stdio servers hang.

COUNTER-ARGUMENTS

Charles Chen "MCP is Dead; Long Live MCP!", Anthropic "Code execution with MCP" (Nov 2025): the discourse conflates stdio MCP (real problems) with HTTP MCP; CLI savings vanish when LLM doesn't already know your custom CLI; MCP wins on multi-tenant, multi-user, cross-platform distribution; Linux Foundation donation is institutional commitment.

VERDICT // MAY 2026

MCP is not dying — it's being right-sized. The hype peak passed; we're in the trough of disillusionment. Consensus is settling around a three-layer model: CLI for inner-loop coding tasks (model already knows the tool), Skills for procedural knowledge, MCP for cross-platform distribution, enterprise auth/audit, multi-tenant SaaS, and services without a usable CLI (Notion, Figma, Slack, Linear). The pattern that wins: "Skills wrapping MCP."

TOON (Token-Oriented Object Notation) — the verdict

Released November 2025 (v1.0, MIT). Drop-in lossless encoding of the JSON data model designed for LLM input. YAML-style indentation + CSV-style rows for uniform arrays. Reference repo (github.com/toon-format/toon, TypeScript) plus ports in Python, Go, Rust, .NET. Token-saving claims: ~40% fewer tokens than JSON in the reference benchmarks; up to 60% for flat tabular data; Webmaster Ramos benchmark (5 formats × 8 scenarios × 3 Claude tiers): TOON −62%, Markdown −53%, YAML −32% vs. JSON.

Adversarial reality (arXiv 2603.03306, Ivan Matveev, Feb 2026): TOON's edge for generation is partly eaten by a "prompt tax" — instructional overhead for one-shot ICL examples. Plain JSON generation is best one-shot for many cases; constrained-decoding JSON sets the lower token-budget bound. TOON wins on heavy-syntax structures (Company case +4.5pp final accuracy, 28% fewer tokens) but loses on deeply nested or non-uniform data (~5% overhead for headers). HN [item 45715632, 45730789] notes the differences become statistically insignificant on better models. No public evidence of large-scale production adoption at OpenAI/Anthropic/Google. Mostly individual benchmarks.

VERDICT

Real but narrow benefit. TOON is a clever optimization for uniform-array, table-shaped prompt inputs, especially with cheap small models, where 30–60% token savings translate to real cost. Not a JSON replacement; a complementary serializer. Worth A/B-testing on bulk classification or extraction over tabular data; not a slam-dunk default for Skippy.

Anthropic's Contextual Retrieval pattern

(Sept 2024, still SOTA): for each chunk, prompt claude-haiku with the entire document + that chunk + "give 50–100 tokens of context locating this chunk in the doc." Cache the document prompt. Index context + chunk in BOTH the embedding and BM25 index.

  • Embeddings alone: ~35% retrieval-error reduction.
  • Embeddings + BM25: ~49% retrieval-error reduction.
  • + rerank on top: ~67% retrieval-error reduction.

This is the highest-leverage RAG pattern published in the last 18 months.

PATTERNS THE FIELD HAS CONVERGED ON

  1. LLM-extracted facts (not raw turns) as storage primitive.
  2. Vector + graph hybrid — pure vector loses temporal correctness; pure graph loses fuzzy recall.

The 2026 reference architecture for personal context engines

Converged across Mem0's State of Memory 2026, Karpathy LLM-Wiki, Granola, Letta, Omi, and Meta's internal Second Brain (60K knowledge workers, per April 2026 Medium post):

CAPTURE → PROCESSING → MEMORY (3-tier) → RETRIEVAL → AGENT/RESPONSE

CAPTURE

  • pendant (Omi over BLE)
  • desktop audio (Granola pattern, no bot in meeting)
  • screen capture (Recall-style, encrypted local)
  • email/calendar/Slack/WhatsApp ingestion via MCP

PROCESSING

VAD (Silero) → diarize (pyannote/Sortformer) → STT (Deepgram Nova-3 or local Whisper) → LLM extraction pass (entities, action items, decisions, people, projects, follow-ups in structured JSON) → daily/weekly compaction & "lint" pass detecting contradictions and aging out stale memories.

MEMORY (THREE TIERS PER MEM0 2026)

  • Working (Redis)
  • Episodic (Postgres+pgvector with time)
  • Semantic (Knowledge graph: Neo4j/Kuzu/Neptune)
  • Plus Karpathy's plain-Markdown wiki as the human-readable "binary" — entity pages with [[wiki-links]].

RETRIEVAL

Hybrid (BM25 + embedding) + reranker on top-K + graph traversal for relationship queries + time-aware decay (Mem0 dynamic forgetting) + classifier routes query to which tier(s).

AGENT/RESPONSE

  • Router (Haiku-style) splits quick-answer vs. agent task
  • Tools-in-a-loop with MCP
  • Background agents for daily summary, weekly reflection, proactive "you committed to X" reminders
  • Surfaces (chat, floating pills, daily digest email, mobile push, glasses display)

CROSS-CUTTING

Eval (Braintrust — note: Gentrace shut down, code on GitHub MIT; Humanloop alive for enterprise) and observability (Langfuse, Arize) tracing every retrieval + LLM call.
